First frames out of the air

Switch the radio on and print raw packets. Thirty lines of code gets you a working packet sniffer — and a bug that takes the rest of this chapter and all of the next one to understand.

Sketch sketches/ch03_first_frames/ch03_first_frames.ino
This sketch is deliberately broken

It works, then stops. Run it, watch the frame counter, and write down the number it stops at before you read chapter 4. The number is the lesson.

The channels

802.15.4 has sixteen channels, numbered 11 to 26, spaced 5 MHz apart:

centre frequency = 2405 + 5 × (channel − 11)  MHz

So channel 11 is 2405 MHz and channel 26 is 2480 MHz. That is the same 2.4 GHz band as Wi-Fi, which matters later: a channel that looks quiet may just be buried under an access point.

The sketch hard-codes channel 21. If that is the wrong guess you will see nothing at all, which is indistinguishable from a broken sketch — chapter 6 builds the scanner that removes the guesswork.

Four calls to start a radio

esp_ieee802154_enable();                // power up the subsystem
esp_ieee802154_set_promiscuous(true);   // deliver everything
esp_ieee802154_set_rx_when_idle(true);  // stay in RX by itself
esp_ieee802154_set_channel(CHANNEL);
esp_ieee802154_receive();               // enter the receive state

The IDF headers are C, so the include needs wrapping or the linker will not find any of these:

extern "C" {
  #include "esp_ieee802154.h"
}

Promiscuous mode is what makes a sniffer

Normally the MAC hardware filters incoming frames by PAN ID and address, and drops everything not meant for it before software ever sees it. Promiscuous mode switches that off, so you get every frame on the channel.

It has two consequences worth knowing now, because they explain things that look like bugs later:

  • A promiscuous node never ACKs. Automatic acknowledgement is part of the filtering machinery, so it goes away too. Your sniffer is completely invisible — which is usually what you want, and is why a second C6 running chapter 7 will not acknowledge the transmitter in chapter 9.
  • set_panid() and set_short_address() stop mattering. They configure the filter you just disabled. Calling them anyway is harmless, and also does nothing.

The callback

The driver calls this function when a frame passes CRC. You do not register it; you simply define a function with this exact name and signature, and it gets linked in:

extern "C" void esp_ieee802154_receive_done(uint8_t *frame,
                                            esp_ieee802154_frame_info_t *frame_info)

The buffer layout is the part to memorise:

frame[0]length
frame[1] … frame[len]the PSDU

frame[0] is the PSDU length including the two-byte FCS field, so a frame reported as 14 bytes carries 12 bytes of header and payload. Chapter 8 is about what is really in those last two bytes, and it is not what the spec leads you to expect.

Frames arrive, then stop. The heartbeat keeps running, so — by chapter 2's logic — the sketch is alive and the radio is not. Note the count it froze at.

If you see nothing at all

Most likely there is genuinely no traffic on channel 21 where you are. You can skip ahead to chapter 6, find a channel that is busy, come back and change CHANNEL. If nothing is transmitting anywhere near you, chapter 9 turns a second board into your traffic source.
