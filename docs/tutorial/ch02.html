Chapter 2

Serial you can trust

Everything from here on is debugged through the Serial Monitor. A sniffer with a broken console looks exactly like a sniffer receiving nothing, and that confusion can cost an afternoon.

Sketch sketches/ch02_serial/ch02_serial.ino

The trap

Nearly every Arduino example contains this line, and on a native-USB board it is a bug:

while (!Serial);   // don't

On a classic Arduino, Serial is a UART and that test passes immediately. On the C6 with USB CDC enabled, Serial is the USB device, and !Serial stays true until a host program opens the port. Run the board from a battery or a plain charger and it sits in that loop forever, looking bricked. The sketch waits, but gives up:

uint32_t deadline = millis() + 2000;
while (!Serial && millis() < deadline) {
  delay(10);
}
delay(300);   // the terminal still misses the first few ms

The trailing delay(300) covers a second quirk: even once the port is open the host's terminal usually drops the first handful of milliseconds. Without it your startup banner is the one message you never see.

If the monitor is empty but the LED blinks

Tools → USB CDC On Boot: Enabled, then re-upload. With it disabled, Serial is routed to the UART pins rather than the USB connector, so the sketch is talking to nobody.

The heartbeat

The sketch prints one line a second, forever:

[  4312 ms] tick 4   heap 318404

This is the single most useful debugging tool in the tutorial, and it is worth understanding why before you need it. In chapter 3 the radio stops delivering frames. The question at that moment is whether the sketch died or the radio did, and those have completely different causes. A heartbeat on an independent timer answers it instantly: if it keeps ticking while frames have stopped, the code is alive and the radio is the problem.

The free-heap column earns its place the same way. A number that drifts steadily downwards is a leak, and watching it is how you catch one before it becomes a crash an hour into a capture.

Checking the chip

setup() also prints what it is running on:

chip: ESP32-C6  cores: 1  flash: 4194304 bytes

If that does not say C6, C5 or H2, stop here — the radio chapters cannot work, because the hardware does not have an 802.15.4 radio on it.
